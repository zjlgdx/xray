# ADR-013: Xray v26.2.6 Alignment and Forward Compatibility

**Date**: 2026-02-28
**Status**: Accepted

**Later policy**: This ADR's stable-only `latest` selection is superseded by the
current [version policy](../../README.md#upgrading-an-existing-server), which
includes published prereleases. The review below remains historical.

## Problem

The project baseline had only been documented up to Xray-core v26.1.23, while the latest stable release is v26.2.6 (released on 2026-02-06). We needed to confirm compatibility, remove stale version guidance, and add maintainability guardrails for future upstream changes.

## Decision

Adopt Xray-core **v26.2.6** as the current stable reference baseline and implement the following:

1. Keep default install channel on stable `releases/latest` only.
2. Harden `latest` resolution and download retry behavior.
3. Surface deprecation/compatibility warnings during deploy and health checks.
4. Add optional VLESS Encryption controls for Reality inbound and generated Reality links, default off.

## Rationale

### 1. Stable-first version policy

Using GitHub stable latest (`/releases/latest`) keeps default behavior conservative and predictable. Pre-release builds remain available through explicit `--version` override.

### 2. Compatibility status for v26.2.6

Current Vision/REALITY topology remains compatible with v26.2.6. No mandatory breaking config changes were identified for the default deployment path.

### 3. Deprecation risk should be visible

Upstream deprecations can become runtime failures in later versions. We now treat known markers as compatibility warnings and expose them in:
- configuration test success path (`xray -test` output parsing), and
- `xrf health` compatibility section.

### 4. Migration direction for deprecated TLS fields

For client/outbound JSON examples and troubleshooting, prefer:
- `verifyPeerCertByName` instead of `verifyPeerCertInNames` / `serverNameToVerify`.
- `pinnedPeerCertSha256` + `verifyPeerCertByName` instead of `allowInsecure`.

These are migration-oriented recommendations; server-side default topology remains unchanged.

## Impact

1. Documentation now points to v26.2.6 as the current stable context.
2. Installer is more resilient to API/network fluctuation when using `--version latest`.
3. Users get actionable compatibility warnings before hard failures.
4. Optional VLESS Encryption can be enabled without changing default behavior.
