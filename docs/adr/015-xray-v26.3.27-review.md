# ADR-015: Xray v26.3.27 Compatibility Review

**Date**: 2026-04-06
**Status**: Accepted

**Later policy**: The v26.3.27 reference baseline below is historical. The
current [version policy](../../README.md#upgrading-an-existing-server) selects
the newest published release, including prereleases.

## Problem

The project baseline was v26.2.6 (ADR-013). Xray-core v26.3.27 (released 2026-03-27) introduces behavioral changes to the REALITY protocol and new warning mechanisms. We need to confirm compatibility, surface new upstream warnings, and document the assessment.

## Decision

Adopt Xray-core **v26.3.27** as the current stable reference baseline. The `realitySettings` config schema is unchanged — no structural modifications required. Implement proactive warnings for two newly identified risk patterns:

1. **Apple/iCloud REALITY destinations**: Warn when users configure Apple or iCloud domains as REALITY `dest`/`serverNames`, as these targets may trigger IP blocking.
2. **Non-443 REALITY port**: Warn when REALITY inbound listens on a port other than 443, which reduces stealth.
3. **Upstream warning surfacing**: Enhance `xray::extract_compat_warnings()` to detect and relay new warning patterns emitted by v26.3.27.

## Rationale

### 1. REALITY `maxUselessRecords` auto-probing (informational)

v26.3.27 introduces automatic probing of the target server's `maxUselessRecords` at startup with four detection levels (default: 32). This is entirely server-side automatic behavior — no configuration field is needed and no action is required from xray-fusion. The feature improves REALITY reliability transparently.

### 2. Apple/iCloud destination risk

Xray now warns at startup when REALITY `dest` points to Apple or iCloud domains (e.g., `icloud.com`, `apple.com`, `cdn-apple.com`, `mzstatic.com`). These targets are known to cause IP blocking for the proxy server. We add proactive validation at install time and configuration time, before the Xray binary even runs.

### 3. Non-443 port stealth reduction

REALITY on non-standard ports is less stealthy because real TLS services on the impersonated domain typically run on 443. Xray v26.3.27 now warns about this. Our default (`XRAY_PORT=443`) is already correct, but users who override it should see the advisory.

### 4. Config schema compatibility

The `realitySettings` JSON block generated by xray-fusion remains fully compatible:
- `show`, `dest`, `xver`, `serverNames`, `privateKey`, `shortIds`, `spiderX` — all unchanged.
- No new required fields introduced in v26.3.27.
- `flow: "xtls-rprx-vision"` remains the correct flow setting.

### 5. Other v26.3.27 changes (no action needed)

| Change | Impact |
|--------|--------|
| TLS ECH `echForceQuery` default → `full` | Not used by xray-fusion |
| uTLS upgrade (new Firefox/Safari fingerprints, X25519MLKEM768) | Fingerprint validator already supports firefox/safari; additive only |
| Finalmask obfuscation methods | Not used by xray-fusion |
| Hysteria 2 inbound support | Not used by xray-fusion |
| XHTTP/3 BBR default congestion | Not used by xray-fusion |
| HTTP headers browser masquerading | Not used by xray-fusion |
| API webhook routing rules | Not used by xray-fusion |

## Impact

1. Documentation baseline updated from v26.2.6 to v26.3.27.
2. Users see proactive warnings when configuring Apple/iCloud REALITY destinations.
3. Users see advisory when using non-443 ports for REALITY.
4. `xray::extract_compat_warnings()` detects new upstream warning patterns.
5. No breaking changes; existing deployments continue to work without modification.
